# 五点式安全带课：第五轮技术调研与验证
日期：2026-11-24

## 结论与边界
保留单文件 HTML、完全离线、浏览器 WASM + Web Worker、教师主控与投影双屏架构。视觉专用模型与专业口述尚未达到业务验收标准；以下是可执行候选路线，而非已完成训练或正式教学验收。releaseReady=false。教学内容、具体教具型号、审定检查卡由课程方确认；本轮不以这些待确认事项阻断工程验证。

## 1. 专用视觉识别
当前 MobileNetV3 是 ImageNet 分类部署探针，只能证明推理可执行，不能判断穿戴是否正确。改用 YOLOX-Nano 检测器，先在许可明确的公开数据上训练人员、安全带存在等类别，再补充同型号部件、局部视角、遮挡与错误样本。输出检测框、可信度、时间戳与取景质量，由几何关系及连续帧规则给出提示；不可见、证据不足或低置信度必须拒判并由教师复核。松紧度、内部扣合、材料缺陷等无法可靠观察的事项不能自动给出安全结论。

- [YOLOX 官方仓库](https://github.com/Megvii-BaseDetection/YOLOX)：Nano 0.91M 参数，416 输入，适合尝试 CPU WASM；[官方 ONNX 导出及推理示例](https://github.com/Megvii-BaseDetection/YOLOX/blob/main/demo/ONNXRuntime/README.md)。
- [Body Harness](https://universe.roboflow.com/construction-images/body_harness)：此前调研页面显示 796 张图，人员/安全带检测；许可标注 CC BY 4.0。
- [Safety Harness Dataset](https://universe.roboflow.com/parkhm/safety-harness-dataset)：此前调研页面标注 CC BY 4.0，可探索安全带与服装区分。
- [Harness and Lanyard Detection](https://universe.roboflow.com/safety-harness-and-lanyard-detect/harness-and-lanyard-detection)：此前调研页面标注 CC BY 4.0，可调查安全带存在及系挂相关类别。
- [YOLO-ILB 论文，Sensors 2026](https://doi.org/10.3390/s26134147)：目标检测与几何规则结合，在305个现场系挂状态验证目标上报告90.82%准确率；其无人机施工场景、模型与数据不同，不是本课穿戴准确率。

上述数据集为候选；下载前固定版本并核实图像来源、实际授权、分类定义、重复样本与训练/测试泄漏。禁止直接把第三方数据或许可不明模型纳入交付。使用跨人、跨场景独立测试集，逐类记录误报、漏报、待核率、延迟、内存、环境及失败案例。优先控制危险错误的误放行；最终阈值与同型号盲测必须由教师审定。

## 2. 中文专业口述
第四轮真人普通话基准：Zipformer 14M 干净/15dB CER 为8.98%/14.37%，Paraformer 为4.19%/5.39%；36条公开真人录音的结果不代表本课专业语句，且不能外推到下述新候选。

候选A：[Paraformer Small INT8](https://csukuangfj.github.io/sherpa/onnx/pretrained_models/offline-paraformer/paraformer-models.html)，上游明确提供79M的 model.int8.onnx，并注明支持普通话及四川话等方言；属于离线识别模型，适合按段录音后解码。需单独核实权重许可、WASM构建接口及单文件大小。候选B：现有Zipformer 14M与[热词增强](https://k2-fsa.github.io/sherpa/onnx/hotwords/)；热词需按模型的token单位及解码器配置，不能假定所有模型均支持。Sherpa-ONNX [WebAssembly官方说明](https://k2-fsa.github.io/sherpa/onnx/wasm/index.html)提供浏览器语音识别路径。采用专业词典、语义规则、否定/疑问/第三人称/漏讲反例和人工复核；严禁单一关键词命中即判完成。优先测试轻量Paraformer候选，对照Zipformer，按CER、关键术语召回、错误接受率、拒判率、响应时延、内存及包体选择。不得把热词推理成功当作识别效果通过。

## 3. Windows Edge 单文件端到端
上轮Windows CI 已证实基础file://、模拟媒体、双窗握手、Worker与零HTTP请求；完整原HTML的双屏及双模型联动尚未通过。官方参考：[getUserMedia安全上下文及权限](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)、[ONNX Runtime Web](https://onnxruntime.ai/docs/tutorials/web/)。
在Windows Edge中将唯一HTML放入空目录，断网测试冷启动、真实模型、教师/投影、授权拒绝/迟到、设备结束、切轮、暂停和重连；监控全部网络请求和页面异常。file://的来源特性及企业安全策略必须实测，跨窗口通信严格校验发送窗口、会话、消息类型及版本；投影仅显示公开字段。保留失败证据，不放宽安全策略绕过限制。

## 4. 稳定性新增真实测试
环境：Linux Node v22.16.0 worker_threads，真实内嵌WASM，模拟输入，不是Edge实机或识别准确率。
三轮各120次视觉推理、5次语音请求，合计360/360与15/15成功；报告峰值RSS 966.2MiB，最后RSS 626.6MiB，基线237.2MiB。前轮汇总视觉P95 21.67ms。完整采样与脚本见 [harness-stress-results.json](harness-stress-results.json)、[harness-stress.cjs](harness-stress.cjs)。Worker销毁后内存未恢复到基线，不应仅凭RSS断定内存泄漏，也不能标记长时间稳定性通过。
下一步：模型常驻复用、限制推理队列与帧率、超时与失败隔离、明确释放媒体轨道和Blob URL；在目标Edge持续运行一节课以上及多轮启停，采集进程内存趋势、时延分位、设备状态和异常恢复结果。
