# 长征课构建发布与验收

[长征课文档指南](AGENTS.md) · [仓库指南](../../AGENTS.md)

以下命令从仓库根目录执行。

## 构建与本地运行

首次构建时从仓库根目录运行 `npm --prefix "课堂演示/自由探索实验" ci` 安装场景依赖。用 Node.js 22.21.0 运行 `node "课堂演示/build.mjs"`，将脚本、样式和媒体内嵌到 `课堂演示/从于都到遵义-课堂演示.html`，同步生成 `展示材料/成果展示/课堂预览.html` 和成果页的共用界面样式。修改课件时先改源码，再重新生成 HTML。用 Edge 直接打开生成文件即可运行。

预览阶段用 `node "课堂演示/build.mjs" --preview` 生成 `.march-build/课件预览/课堂预览.html`。先保存任务起点的正式 HTML 并实走旧错例，用 `Test/course_cli.py --html <文件>` 对预览执行相同操作。接入正式版后运行 `node "课堂演示/build.mjs" --check` 校验正式文件和成果预览，再核对已通过验收的预览校验值。

### 发布离线成品

- Git 提交源码、运行素材、构建脚本和手工维护的 HTML 页面。发布用的生成 HTML 成品直接作为 GitHub Release 附件交付。长征课正式 HTML、成果页的课堂预览 HTML 和成果 ZIP 在本地生成，由 `.gitignore` 排除。成果页源码留在 Git，课堂预览随成果 ZIP 发布。
- 发布前从仓库根目录依次运行 `node "课堂演示/build.mjs"`、`node "课堂演示/build.mjs" --check` 和 `python -B "展示材料/成果展示/build-zip.py"`。在空目录断网检查正式课件和解压版的入口，核对 ZIP 内课件与正式 HTML 的 SHA-256。
- 推送源码后，以该提交创建对应版本的 GitHub Release。将 `课堂演示/从于都到遵义-课堂演示.html` 和 `展示材料/成果展示/沉浸式VR课程-从于都到遵义-成果展示包.zip` 作为附件上传。发布后核对标签指向、下载文件和本地 SHA-256。

另行展示两套实验时，按[室内与河岸样课](../../展示材料/遵义自由探索原型/对照与复跑.md#复跑)和[遵义会议桌三种路线](../../展示材料/遵义镜头路线对比/实测与路线选择.md#从源码复跑)生成成品。需要对外分发时随对应版本提供，生成文件由 `.gitignore` 排除。

## 验收

本地用 `npm --prefix "课堂演示/自由探索实验" run check:course` 执行类型检查。普通 GitHub Actions 检查构建、界面规则和断网 Edge 单屏入口，再按改动加跑短用例。需要完整回归时手动运行[长征离线课件工作流](../../.github/AGENTS.md)，或用本地验收脚本复跑专项。

| 长征课要求 | 验收方式 |
| --- | --- |
| 局部改动边界 | `node "Test/verify-lesson-scope.mjs" --base <任务起点> --allow <文件>` 核对文件范围。共享文件可用 `--range 文件:起行-止行` 限定基线区段，选定范围后实走相关入口。 |
| 三维自由探索 | 按章检查可玩场景与实际动作。试不同顺序、直接操作和回看，观察学员能否从画面反馈理解先辈的处境与行动。 |
| 自然美术与轻透界面 | 用实际机位从远近和侧后核对可见环境、比例、材质、光线和接触。在明暗背景下验透景、可读性、跟手响应和连贯性。 |
| 影视衔接以实际课页为准。外部素材记录来源和许可，转场由画面、物件或声音承接。 | 开场分镜与素材见 `opening-sources.md`。`python -B "Test/verify-course-media.py" --check-join opening terrain yudu-assembly` 核对开场的 Edge 解码首尾帧。各短片使用实际入图和出图的资源键，例如 `--check-join yudu-preparation yudu-bank yudu-bridge`。用正常速度验实际切换、讲解和暂停续播。 |
| 湘江渡口短片的首尾帧要与实际前后课页对齐。 | `Test/verify-xiang-crossing.py` 从真实翻页路径取「湘江河谷」和「湘江留下的启示」底图，直接与 Edge 解码帧比较。首或尾的平均 RGB 差超过 3/255，GitHub Actions 的湘江回归失败。 |

按[验收技能](../../.agents/skills/verify-long-march-course/SKILL.md)选择课页操作、专项入口和证据目录。

运行 `python -B "Test/verify-desk-live.py"` 专测桌景绕看、手记翻页、路线对照、窄窗和返回恢复。用 `--html <预览文件> --output <证据目录> --record` 留下截图、报告和 Edge 录屏。

运行 `python -B "Test/verify-desk-art.py" --before <原成品> --after <预览> --output <证据目录>` 拍摄桌景同机位和纸件运动对照，交替采集本机 Edge 的翻页完成时间与浏览器帧间隔。

构建课件后，用 `Test/course_cli.py` 在离线 Edge 核对首页、开场、课页、练习、路线、桌景与回顾。脚本把 HTML 单独复制到空目录。材料厅带入桌景的线索用 `Test/verify-route-interactions.py --desk-only` 实走，试讲用时和后排可读性用实际教室设备检查。

构建和发布产物排除 `Test/`。

## GitHub Actions

本地用 `python -B "Test/run-course-ci.py" plan --full` 生成全量验收清单，再用同脚本的 `run` 执行。

- 普通分支 push 和 pull request 从源码生成并核对离线课件，检查类型、界面规则和成品入库情况，再用断网 Edge 验单屏入口。片头、进场、故事卷宗或回顾源码有对应改动时，加跑相应短用例。只改 Markdown 或推送 Release 标签时跳过此工作流。
- 多尺寸视频、路线、三维专项及其他长用例保留在 GitHub Actions 的「长征离线课件」手动运行中。点「Run workflow」后，可填一个检查名复跑，例如 `desk-live`。留空时，14 项 Edge 回归分四组运行。普通检查的上限为 10 分钟，手动运行每组的上限为 20 分钟。
- Pull request 比较基线到实际检出的合并结果，push 比较更新前后的提交。浅检出缺少基线时按提交补取，仍无法比较时执行单屏入口检查。失败组上传选测清单、课件 SHA-256、构建日志和浏览器证据。
- 更新路径或依赖后，从仓库根目录复跑受影响的命令。可复用的检查代码放在 [Test](../../Test/AGENTS.md)。
- Ubuntu runner 在断网验收前安装 Noto CJK 字体。软件渲染使用半倍像素密度，测试窗口的布局尺寸照原值执行。正式课件画质和教室投影用 Windows Edge 核验。
- 云端桌景专项实走 1366×768 和窄窗回退。1920×1080 的完整桌景操作随本地桌景专项验收。
